# Masha · Psychology BA 2027

Локальное веб-приложение для плана поступления Маши на Psychology BA (Западная Европа, старт — сентябрь 2027).
Работает полностью в браузере: без backend, без API-ключей, без облачных сервисов и сетевых запросов.

**Стек:** React 18 · TypeScript · Vite · Tailwind CSS · Radix UI (диалоги, меню, поповеры, подсказки) · Recharts ·
date-fns · framer-motion · Dexie (IndexedDB) · zod · sonner · canvas-confetti · Vitest.

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fnpolllll%2Fmasha-psychology-ba-2027&project-name=masha-psychology-ba-2027&repository-name=masha-psychology-ba-2027)

## Быстрый старт

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # проверка типов + production-сборка в dist/
npm run preview    # просмотр сборки: http://localhost:4173
npm run test       # Vitest (домен, хранилище, smoke-тест интерфейса)
```

Требуется Node.js 18+.

## Источники данных

Все исходные данные — в `src/data/seed.json`, сгенерированы напрямую из Excel и сверены с JSON из ТЗ (совпадение полное):

- **49 задач** и **9 этапов** со статусами на 10.10.2026: 9 «Готово», 1 «В работе», 39 «Не начато».
- Колонка Excel **«Результат»** перенесена в поле `result` (в seed ТЗ её не было).
- `conditional: true` — условные задачи («если…»): 0.4, 3.4, 3.8, 4.5, 4.6, 7.3.
- Вкладка «Ориентиры по Европе» — `europeGuidelines`.
- Текст мастер-плана DOCX (вехи, условия закрытия, «Важно для ТЗ», строки «Старт → финиш» этапов) — `src/data/plan.ts`.

Seed записывается в IndexedDB **один раз** — при создании новой базы (`Dexie.on('populate')`). Повторные запуски
и перезагрузки статусы не сбрасывают.

## Логика расчётов (Excel → приложение)

| Excel | Приложение (`src/domain`) |
| --- | --- |
| «Этапы»: Старт `MINIFS`, Финиш `MAXIFS` | `computeStageStats` — min(startDate) / max(dueDate) живых задач этапа |
| «Задач», «Готово», «Прогресс» | Прогресс = «Готово» / применимые задачи (без «Не требуется») |
| «Статус» этапа | «Закрыт» — все применимые задачи «Готово» **и** вручную подтверждено условие закрытия; «В работе» — есть задача «В работе»/«Готово»; иначе «Не начат» |
| «Ближайший открытый дедлайн» | `nearestOpenDeadline` + «ближайшее действие» этапа |
| «Дней до дедлайна» = E − TODAY() | `daysBetween(today, dueDate)` по календарным датам в выбранной таймзоне |
| «Сводка»: просрочено, дедлайн в ближайшие 14 дней, общий прогресс | `computeOverall` |
| «Жёсткие дедлайны» = `SORT(FILTER(Жёсткий, ≠Готово))` | `openHardDeadlines` — производный фильтр, не копия вкладки |

Отличие от Excel, заданное ТЗ: в Excel «Отменено» прибавлялось к «Готово». В приложении есть отдельный статус
**«Не требуется»** — задача исключается из знаменателя (и не считается выполненной). Ставится только после подтверждения.
При импорте Excel-статус «Отменено» превращается в «Не требуется», «Блок» — в «В работе».

**15.01.2027** — общий ориентир, а не подтверждённый дедлайн каждого вуза. Даты задач этапа 4 позже 15.01 (запасная
волна, интервью) не «исправляются» — они показаны как ориентиры, а расхождение описано в разделе «Описание».

## Ежедневная сводка (без LLM)

`src/domain/summary.ts` — детерминированные шаблоны из фактических дат и статусов. Приоритет:
просроченные жёсткие → жёсткие сегодня → остальные сегодня → просроченные прочие → завтра → через 2–3 дня →
в работе (статус или период start ≤ сегодня ≤ due) → скоро старт → спокойное состояние. В карточке показываются 1–3
самых важных факта. Сводка никогда не пишет «нет задач», если есть активные.

`now` обновляется раз в 60 секунд, а также при `focus`/`visibilitychange` (смена дня, ручное изменение системного времени).

### Режим проверки даты

Для проверки сценариев просрочки можно подменить «сегодня»: `http://localhost:5173/?today=2026-11-05`.
Режим виден в боковой панели («режим проверки даты») и сохраняется до закрытия вкладки; выключить — `?today=off`.

## Хранение и данные

- **IndexedDB** (Dexie), база `masha-psychology-ba-2027`, версия схемы **v1**. Таблицы: `tasks`, `stages`, `events`,
  `settings`, `links`, `meta`. Новые версии схемы добавляются через `db.version(N).upgrade(...)`, экспортные файлы
  мигрируются функцией `migrateExport`.
- Каждое изменение сохраняется сразу и транзакционно вместе с записью в журнал (`created`, `updated`, `statusChanged`,
  `deleted`, `restored` — дата/время, ID задачи, старые/новые значения).
- Удаление мягкое: задачу можно восстановить из toast «Отменить» или из «Истории изменений».
- Новые задачи получают UUID и читаемый ID внутри этапа (`0.6`, `3.11`) без коллизий, в том числе с удалёнными.
  Исходные ID не меняются.
- **Экспорт JSON** — полный снимок (задачи, этапы, журнал, настройки, ссылки) с версией схемы.
- **Импорт JSON** — проверка схемы (zod), предпросмотр изменений (новые/изменённые/удаляемые задачи, смены статусов),
  затем транзакционная замена. Принимается и формат `seed.json`.
- **CSV** — задачи в UTF-8 с BOM, разделитель «;» (открывается в Excel с русской локалью).
- **Сброс** — двойное подтверждение (диалог + ввод слова «СБРОС»), возвращает исходный Excel.

## Supabase

Публичный (publishable) ключ прописан в `.env` как `VITE_SUPABASE_ANON_KEY` — такие ключи по замыслу Supabase
встраиваются в клиентский код, а данные защищаются политиками Row Level Security. Секретные ключи (`sb_secret_…`)
в репозиторий не добавлять. Для подключения заполните `VITE_SUPABASE_URL` (Project Settings → API → Project URL);
клиент доступен через `getSupabase()` из `src/lib/supabase.ts` и возвращает `null`, пока URL не задан.
Статус конфигурации виден в «Настройки → Данные». Сейчас приложение хранит данные локально и Supabase для
синхронизации не использует.

## Деплой на Vercel

В корне лежит `vercel.json` (Vite, `npm run build`, папка `dist`, SPA-rewrite на `index.html` для прямых ссылок
вроде `/tasks`). Варианты:

1. Кнопка **Deploy with Vercel** выше — Vercel клонирует репозиторий и соберёт проект.
2. Vercel Dashboard → **Add New → Project → Import** репозиторий `npolllll/masha-psychology-ba-2027` → Deploy.
   Настройки определятся автоматически; переменные окружения уже в `.env`.
3. CLI: `npx vercel --prod` из корня проекта (после `npx vercel login`).

После подключения репозитория каждый push в `main` деплоится автоматически.

## Дизайн и доступность

Светлая тема по референсу: фон `#F7F8FB`, карточки `#FFF`, текст `#182033`, акцент `#FF2D70`, вторичный `#8790A3`,
успех `#20C997`, предупреждение `#F2A33A`; радиусы 16–22px, мягкие тени, шрифт Inter (локально, `@fontsource`).
Фото городов в окружении недоступны, поэтому панорама Флоренции, небо, арка и улица — собственные SVG-иллюстрации
(никаких внешних загрузок). Sidebar 240px; на ширине < 1024px — верхняя панель и нижняя навигация (проверено на 390, 768,
1440px). Диалоги с фокус-ловушкой и Esc (Radix), aria-label на иконках, aria-live для сводки и уведомлений, анимации
150–300 мс, `prefers-reduced-motion` отключает анимации и конфетти.
